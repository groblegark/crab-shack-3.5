# FOODWAYS & MANAGEMENT AS DATA — CS3 codebase map + prior art

All refs `/Users/matthewbaker/crab-shack-3/game.js` unless noted (16,211 lines). Personality tables in `/Users/matthewbaker/crab-shack-3/crabs.js`.

## A. CODEBASE: THE FOOD/GOODS/COMMERCE LAYER

### A1. Menus / dishes / catalogs — ALREADY A DATA TABLE (but a code literal, not save data)
- `const BIZ = {...}` **142–303** is the whole catalog. Per business: `name/short/sign/kind/rent/owner`, geometry (`x0/x1/door/queueX/park/rack`), `stations` (named→coords), `tables`/`stalls`, `source`/`out`, and `recipes`.
- **Recipe shape** (uniform across food, arcade games, showers, hotel rooms): `{ id, icon, pay, raw, raw2?, steps: [[stationKind, seconds, productIcon], ...], showerT?, deep? }`. Shack: taco $17 / juice $10 / grill fish $13 (**170–177**); juicebar: juice $6 / cooler $9 (fruit+water) (**210–215**); arcade "recipes" are games (**190–197**); hotel's one recipe is A NIGHT'S STAY (`room`, raw `linen`) (**271–274**); showers rinse/soak (**296–301**). *A "dish" is already fully generalized — anything with steps and a price is a dish.*
- Display names: `ITEM_NAMES` **4787–4793**; `DRINKS = {juice, cooler}` **4795** (thirst-quenching set — a one-line "food category" table).
- **NOT in the save**: recipes/stations live only in the BIZ literal. The save (**6205–6315**) persists per-biz *settings maps* (`hours`, `mealPol`, `tipShare`, `price`, `wage` — 6263–6310) keyed by biz id, but the menu itself is code. This is the single biggest 3.5 migration: the settings envelope pattern already exists; the catalog just needs to join it.

### A2. Pricing — FORMULA over the data table
- `menuPrice(b,r) = max(1, round(r.pay * bizPriceMul(b)))` **439**; per-shop `priceMul` 0.7–1.3 in 5% steps (**434–438**), persisted (**6268**). Locals pay +25%: `localPrice` **463**. Staff meals: `staffMealCharge` **479–482** via 3-value policy `MEAL_POLS = [retail, atcost, free]` **381**.
- Demand response: `priceAppeal(b) = clamp(0.6..1.6, (1/mul)^1.2)` **475–478** (`PRICE_ELAST` 468); base footfall shares `TOURIST_PULL = {shack:.5, arcade:.22, juicebar:.3}` **472** — a hardcoded const, prime culture-data candidate.

### A3. Ingredients, imports, trade ledger — DATA TABLE + one price formula
- `INGREDIENT_COST = { fish_raw:5, fruit:3, token:1, soap:1, linen:2 }` **4714**; `IMPORTS` table (fish/corn/water/power/fruit/paper with name/unit/price) **4724–4734** — the ferry's manifest, explicitly built as "the town is a NODE" for future trade tiers (T1 bookkeeping now).
- `trade` state **4735–4748**: totals/day flows, `spentBy` per good, fish price series. `tradeImport()` **4749**; `consumeIngredient()` **4776–4786** (fruit/water tracked; fish decrements `townCatch` else auto-imports at $7).
- **Fish price discovery** `settleFishMarket()` **4760–4771**: 3-day supply/demand windows, $1 steps, floor $2 / import-ceiling $7 (`FISH_FLOOR/FISH_IMPORT/FISH_START` 4720). `ingredientCost()` **4772–4775**: fish floats, everything else fixed. Woven formula, but small and self-contained.
- **Soup pot** (the charity foodway): consts **122–127** (`SOUP_AT/SOUP_SICK_AT/SOUP_FILL/SOUP_MINS/SOUP_CD`), `SOUP_MARGIN` 675, `bowlCost()` 1088, `SOUP_BIZ="shack"` 1237, pot restock buys bowls from the shack on the town ledger **1244–1256**. A "communal dish" is thus already a distinct mechanic with its own economics — a culture-flavorable institution.

### A4. How eaters choose dishes — FORMULA, with a HOLE where taste should be
- **Visitors** (`visPick` **9618–9694**): candidate per need (food→shack, drink→juicebar else shack, clean→showers, fun→arcade, room→hotel), gated by `visOpen` (unlocked+lit+hours+staffed, 9608) and queue room (`TOURIST_QUEUE_MAX=4` line 33). Affordability = `menuPrice + room reserve` (**9626**). Scorer: `s = (VIS_RANK[need] + needLevel) * priceAppeal(biz) / (1 + dist/DETOUR_SCALE)` **9689**. Dish within shop: **`treat` = uniform random over affordable recipes** (**9646–9653** — deliberate: holidaymakers "order what they fancy"; locals' cheap-when-poor rule was measured to kill ticket size). **There is no per-dish preference term anywhere — this is the exact plug point for cultural tastes.**
- Rejections are typed and recorded: `stayBlocked(k, "shut"|"full"|"broke")` **9636–9641, 14660** — the departure card names which failure dominated (**14665–14691**). Adding a 4th reason ("nothing I eat") is structurally trivial.
- **Locals** (`pickErrand` ~**7479–7660**): eat cheap under $40 wallet, random treat above (**8259**); staff self-cook at own shop through `staffMealCharge`; drinks route juicebar-first (**7554–7567**).
- Visitor demography is formula-from-consts: needs rates `VIS_RATE`/thresholds `VIS_WANT`/priorities `VIS_RANK` **9179–9187**; boat size from reputation `FERRY_BASE/FERRY_REP` **9121**; wallet minting incl. rep-scaled flush share **9252–9293** (`REP_FLUSH_*`, `REP_PURSE_*` 9128–9129); four sailings `FERRY_TIMES` **9099**.

### A5. Cooking skill / dish mastery — DATA-ADJACENT, already per-dish-id
- `p.made` = **dish-id → lifetime count** on the persona (**5760**, incremented **8805**), persisted with personas. `MASTERY = [[250,0.20,"MASTERED"],[100,0.12,"IS FAMOUS FOR"],[25,0.05,"HAS THE KNACK FOR"]]` **8762**; `masteryMult` divides step time (**8736, 8763–8766**). Fishing rides the same ladder (`FISH_TIERS` **8775–8785**). *Because mastery is keyed by arbitrary dish id, foreign recipes get progression for free — but there is no "knows/doesn't know" gate; every crab can cook every recipe at their shop.*

## B. CODEBASE: THE MANAGEMENT LAYER (what a culture would flavor)

- **Hours**: per-biz `{open, close}`, 30-min grain, bounds 6:00–24:00/≥4h (**314, 383–414**); gates tourists, errands, CLOSED sign; persisted 6263. NPC owners self-tune via `HOURS_POLICY` table **1870–1882** + `runHoursPolicy` **1901+** (extend/later/earlier off queue-at-close + dead-hour signals).
- **Shifts**: DERIVED from hours — `SHIFT_SPAN = {M:360, E:360, D:600, cover:720}`, M=first half/E=second half/D=owner open+30..close−90, capped-and-centred `bizShiftWindow` **4110–4127**. Overtime `OT_SPAN=120, OT_RATE=1.5, OT_FATIGUE=1.5`, strictly inside open hours (**4192–4219**). Sick policy `grant|require` **4149–4158**; convalescence ladder `CARE_LANES` **4180–4185**.
- **Wages**: three layers, most-specific-wins: `WAGE_STD=23` → `BIZ[b].wage` → per-crab private deal stamped with owner (`p.wage/p.wageOwner`, lapses on employer change) **315–380**; min-wage law clamps at set-time `legalWage` **358**. NPC wage AI `WAGE_POLICY` + `runWagePolicy` **4658–4704** (raise on grievance/stale post, trim above going×1.12).
- **Tips**: table-service culture encoded as consts — `TABLE_TIP=9` flat table tip **8849**, counter pays token ×`TIP_COUNTER=0.15` **8828**; live tip = `menuPrice × 0.5 × patience/maxPatience × trait.tip × (1−0.3·dirt)`, clamped to guest wallet (**8931–8949**). Owner's `tipShare` slider (0–1, 5% grain) splits every tip crab-vs-till in exactly one place, `payTip` **8851–8877**; persisted 6265. `TRAITS[].tip/work/move` multipliers in `crabs.js:8–57` (cheery tips ×1.25, grumpy ×0.9).
- **Hiring**: `jobBoard` postings `{biz, wage, day}` **5020**; NPC owners post at till thresholds, stale postings reach bus-in drifters, pier posts when fish pins at ceiling (`runJobBoard` **7060–7099**); wage-vs-pier reservation `recruitBites` **7196**. **Player hires prefer converting a tourist mid-visit** (`hireCrew`→`convertTourist` **7197–7224, 7167**) — the pig-settler pipeline already exists.
- Verdict: management is ~90% data already (per-biz scalar settings + small policy tables), all persisted; what's frozen is the *defaults and norms* (WAGE_STD, TABLE_TIP, TIP_COUNTER, MEAL_POLS semantics, SHIFT_SPAN shapes) — i.e., exactly the "conventions" a culture section would own.

## C. WEB PRIOR ART

**(a) Recipes as data**
- **CDDA**: every dish is JSON — `{type:"recipe", result, category, skill_used, difficulty, time, autolearn, qualities, tools, components}` with recipes in `data/json/recipes/food/`; `autolearn:false` + book/NPC-taught recipes make *recipe knowledge itself an ownable datum*. Closest shape to CS3's `{id, pay, raw, steps}` — proof the whole catalog can live in a file. ([JSON_INFO](https://docs.cataclysmdda.org/JSON/JSON_INFO.html), [repo recipes](https://github.com/CleverRaven/Cataclysm-DDA/tree/master/data/json/recipes/food), [contributor guide](https://github.com/CleverRaven/Cataclysm-DDA/wiki/New-Contributor-Guide---Recipes))
- **Dwarf Fortress raws**: workshop "reactions" (reagents→products, material-property-driven via `MATERIAL_REACTION_PRODUCT`) are fully moddable text data; the cautionary half: *meals* are a hardcoded vanilla job, so modded cuisines can't cater to preferences — the exact trap CS3.5 is trying to avoid. ([Reaction](https://dwarffortresswiki.org/index.php/Reaction), [examples](https://dwarffortresswiki.org/index.php/DF2014:Reaction_examples))
- **BotW cooking**: compositional rather than tabular — ingredient carries effect+points, first/duplicate rules, clashing effects cancel, tier thresholds. Instructive as the *emergent hybrid dish* model (combine tags, get a new dish) but a worse fit for CS3's station-steps machine than CDDA's fixed table. ([Zelda Dungeon cooking](https://www.zeldadungeon.net/wiki/Cooking_in_Breath_of_the_Wild), [GameFAQs mechanics guide](https://gamefaqs.gamespot.com/wii-u/632936-the-legend-of-zelda-breath-of-the-wild/faqs/74776))

**(b) Cultural diffusion in shipped games**
- **CK3 Royal Court**: cultures = 5 pillars (heritage/language/aesthetics/martial/ethos) + tradition list; **acceptance** is a 0–100 scalar between culture pairs grown by contact/intermixing/granting titles; at ≥40 you may **hybridize**, cherry-picking pillars+traditions from both parents, and the hybrid starts at 100% acceptance with both. The cleanest "cultures are lists of swappable data blocks + a learned-tolerance meter" model in a shipped game. ([CK3 wiki Culture](https://ck3.paradoxwikis.com/Culture), [PC Gamer](https://www.pcgamer.com/crusader-kings-3-ck3-hybrid-culture/), [Gamerant](https://gamerant.com/crusader-kings-3-ck3-how-diverge-hybridize-cultures/))
- **Victoria 3**: per-culture **obsessions** and per-religion **taboos** on consumer goods — obsession sets min weight 1 and ×2 the buy-weight, taboo ×0.5, ±25% on the containing need; obsessions *emerge dynamically when a good is abundant in the pop's market* — i.e., exposure creates taste. Directly the pork-bun mechanic. ([Dev Diary #56](https://www.paradoxinteractive.com/games/victoria-3/news/dev-diary-56-cultures-and-religions), [Needs wiki](https://vic3.paradoxwikis.com/Needs), [AltChar](https://www.altchar.com/guides/victoria-3-how-taboos-and-obsessions-work-aOOlA8j6N8pO))
- **Ultima Ratio Regum**: the maximalist reference — generated societies with own ideologies, dialects, clothing, aesthetics; national cuisines planned-not-shipped. Useful as ambition ceiling and as evidence cuisine-gen is the hard leftover. ([Game Developer 10-year retrospective](https://www.gamedeveloper.com/design/the-10-year-journey-of-ultima-ratio-regum-the-culture-generating-roguelike), [about page](https://www.markrjohnsongames.com/games/ultima-ratio-regum/))
- **Cuisineer**: customer *types* demand specific dishes and sulk without them; menu limited to recipes you've learned + equipment tier — recipe-knowledge-as-progression in a cozy restaurant sim. ([Steam](https://store.steampowered.com/app/1963570/Cuisineer/), [TheGamer](https://www.thegamer.com/roguelike-restaurant-management-game-cuisineer-is-all-its-cracked-up-to-be-and-more/))
- **Anno 1800 Tourist Season**: restaurants are venue-shells that mount one **recipe** (3 input goods → distinct buff/satisfaction); recipes unlock via tourist quests; tourist satisfaction throttled by town attractiveness. Model for "menu slot" data and tourists-as-recipe-unlock-vector. ([Restaurant wiki](https://anno1800.fandom.com/wiki/Restaurant), [Tourist Season DLC](https://anno1800.fandom.com/wiki/Tourist_Season_DLC))

**(c) Tourist preference systems**
- **RollerCoaster Tycoon** remains the canon: each guest carries needs (hunger/thirst/nausea/bladder) + fixed personal preferences (intensity/nausea tolerance), picks nearest satisfier, and — the important part — **verbalizes the decision as thoughts** ("I'm hungry", "It's too expensive"), making an invisible preference vector debuggable/legible. CS3's departure card + typed `stayBlocked` reasons already reimplement this pattern; extend, don't invent. ([Guests and Staff](https://rct.fandom.com/wiki/Guests_and_Staff), [Guest Moods](https://rct.fandom.com/wiki/Guest_Moods), [Nausea](https://rct.fandom.com/wiki/Nausea))

## D. PAYOFF 1 — FOODWAYS AS A CULTUREWAY SECTION (what the save schema expresses)

A culture's `foodways` block, superseding today's code literals; everything below already has a live variable to bind to:

```
culture.foodways = {
  ingredients:  { pork:{name,unit,importPrice}, ... }          // extends IMPORTS(4724)+INGREDIENT_COST(4714)
  recipes:      [ {id, name, icon, price, raw, raw2?, steps:[[station,secs,product]],
                   tags:["drink"|"plate"|"treat"|"staple"], culture:"pig",
                   knowledge:"open"|"taught" } ]               // BIZ[b].recipes(170-301) + DRINKS(4795) + ITEM_NAMES(4787)
  venues:       [ {kind, stations, tables/stalls, defaultMenu:[recipeIds], pullBase} ]  // BIZ geometry + TOURIST_PULL(472)
  communal:     { dish, fillFrac, margin, queueMins, threshold } // the soup pot block (122-127, 675, 1237)
  tastes:       { dishTag|recipeId -> weight }                 // NEW: Vic3-style obsession/taboo multipliers; plugs into visPick 9652/9689
  visitorProfile:{ rates:VIS_RATE, wants:VIS_WANT, ranks:VIS_RANK, purse:{...}, patience }  // 9179-9187, 9252-9293
  management:   { wageStd, wageBand:[min,max], tipTable, tipCounterFrac, tipShareDefault,
                  mealPolDefault, sickPolDefault, shiftShapes:SHIFT_SPAN, otRate, otSpan,
                  hoursDefault, priceElast, localMarkup }      // 340-341, 8828/8849, 381, 4110-4111, 4206-4208, 463, 468
  diffusion:    { acceptance:{otherCulture->0..100},           // CK3-style, saved town-level
                  perAgent: p.made (already saved), p.knows:[recipeIds], p.tastes:{id->weight} }
}
```
Key facts making this cheap: the save already carries per-biz maps for hours/wage/price/tipShare/mealPol (**6263–6310**), personas already carry per-dish counters (`p.made`), and every consumer decision funnels through 4 functions (`menuPrice`, `visPick`, `pickErrand`, `staffMealCharge`).

## E. PAYOFF 2 — CROSS-CULTURAL MECHANICS WORTH STEALING

1. **Taste weights with exposure drift (Victoria 3 obsessions/taboos).** Give every agent/culture a `tastes` multiplier map over dish tags; pigs land with `pork_bun:2.0, fish_taco:0.5`. Multiply into `visPick`'s currently-uniform `treat` picker (game.js:9652) and scorer (9689). Steal Vic3's emergence rule verbatim: *abundance creates obsession* — a pig who eats fish tacos 3 visits running flips their taco weight up; a town that never stocks pork keeps pigs' wallets going home (already measurable via the `broke/shut/full` counters — add `"foreign"`). Numbers to copy: ×2 obsession, ×0.5 taboo. ([Vic3 DD#56](https://www.paradoxinteractive.com/games/victoria-3/news/dev-diary-56-cultures-and-religions))
2. **Acceptance meter gating hybridization (CK3).** One scalar per culture-pair, town-level, saved; grown by completed cross-cultural transactions (pig eats crab dish, crab crew serves pig table, pig hired via the existing `convertTourist` path 7167/7203). Thresholds unlock: pigs patronize non-shack venues (multiplies `bizPullBase`), pig recipes become postable on crab menus, and finally a **hybrid dish** built by cherry-picking steps from a parent recipe of each culture — CK3's pick-your-pillars screen as a menu editor. ([CK3 Culture](https://ck3.paradoxwikis.com/Culture))
3. **Recipe knowledge as a taught item (CDDA `autolearn:false` + Cuisineer).** Split "recipe exists on this menu" from "this cook can make it": foreign-tagged recipes require `p.knows[id]`, acquired by (a) working a shift beside a knower — mirrors the contagion mechanic that already keys on standing beside a sick colleague (4143–4146) — or (b) repetition at a stiff time penalty, reusing `masteryMult`'s per-dish-id machinery (8736, 8762) as the *learning* curve, not just the mastery curve. A pig settler is then economically valuable as a knowledge carrier, not just labor. ([CDDA JSON_INFO](https://docs.cataclysmdda.org/JSON/JSON_INFO.html))
4. **Legible refusals (RCT guest thoughts → CS3 departure card).** Add `stayBlocked(k,"foreign")` when a pig's affordable candidates all fall below a taste floor, and a `DEPART_RULES` quote row ("NOT A PORK BUN IN TOWN. I ATE FISH, I SUPPOSE.") — the 80/70-weight band (14742–14746) already prices exactly this kind of failure in reputation. The player learns the demand exists *from the guests' mouths*, before any pig venue is buildable — RCT's core trick. ([RCT Guests](https://rct.fandom.com/wiki/Guests_and_Staff))
5. **Menu-slot venues + tourists as unlock vector (Anno 1800 Tourist Season).** Make a shop's active menu a data list of recipe ids (today it's the whole `BIZ[b].recipes` array, always-on), so the same shack shell can mount pig dishes once learned; and let *visiting pigs issue the unlock* (Anno's tourist quests → CS3: serve N pigs / hire a pig / acceptance threshold hands you the pork-bun recipe card). This also cleanly carries the reverse flow: a crab recipe boarding the ferry to the mainland as an export. ([Anno Restaurant](https://anno1800.fandom.com/wiki/Restaurant))
