# FIXED-POINT FORMAT DESIGN + PRIOR ART — CS3.5 deterministic core

## 1. PRIOR ART — what shipped determinism actually looks like

**Doom (Q16.16 `fixed_t`)** — [m_fixed.h](https://github.com/id-Software/DOOM/blob/master/linuxdoom-1.10/m_fixed.h): `FRACBITS=16`, `FixedMul = (int64)a*b >> 16` (truncating shift — floor toward −∞ on the arithmetic-shift path), `FixedDiv = ((int64)a<<16)/b` ([DoomWiki fixed point](https://doomwiki.org/wiki/Fixed_point)). Angles are **BAM**: full u32 = one turn, shifted down 19 bits into 8192-entry `finesine`/`finetangent` tables shipped as **baked literals** in [tables.c](https://github.com/id-Software/DOOM/blob/master/linuxdoom-1.10/tables.c) ([BAM overview](https://en.wikipedia.org/wiki/Binary_angular_measurement), [table structure](https://bookdown.org/robertness/doom_tour/7_11_rendering_lookup_tables.html)). The killer precedent: the tangent table is **known-wrong and kept wrong** ([Inaccurate trigonometry table](https://doomwiki.org/wiki/Inaccurate_trigonometry_table)) because demo playback (their fingerprint) depended on the frozen values — exactly the CS3.5 re-baseline philosophy: *bake the table, freeze the baseline, never recompute with libm at runtime*.

**Age of Empires ("1500 Archers")** — [Terrano/Bettner 2001](https://www.gamedeveloper.com/programming/1500-archers-on-a-28-8-network-programming-in-age-of-empires-and-beyond) ([PDF](https://zoo.cs.yale.edu/classes/cs538/readings/papers/terrano_1500arch.pdf)): lockstep = ship only commands, every machine runs the identical sim; desyncs detected by periodic **state checksum**; seeded shared RNG; recorded games double as repro cases (= your 16-seed matrix + frozen fingerprints, invented 25 years ago). Their war stories: desyncs came from *any* nondeterminism — RNG draws outside the sim, iteration order, uninitialized reads — not only floats. Lesson: the fingerprint hash is the institution; the numeric format is just what makes it cheap to keep green.

**Factorio (the opposite pole: doubles, same binary)** — chose to *keep* floating point but ship identical binaries per platform and write their **own trig** so libm variance can't bite ([forum: float point and why](https://forums.factorio.com/viewtopic.php?t=52747)); 500-player cross-OS sessions hold sync ([FFF-340 discussion](https://forums.factorio.com/viewtopic.php?t=82891&start=60)). Their one real float desync was compiler-level (`float*float` computed via double on one build) — i.e., *doubles-but-same-binary works only when you control the binary*. **CS3.5 cannot**: JS engines are the "compilers" and you ship source. But Factorio still validates two of your choices: (a) **positions are fixed-point int32, 1/256 of a tile** ([MapPosition docs](https://lua-api.factorio.com/latest/concepts/MapPosition.html)) — precedent for Q8; (b) desync reports serialize floats as hex and their map-gen desync was an **ambiguous sort comparator** ([Desynchronization wiki](https://wiki.factorio.com/Desynchronization)) — see risky decision #5.

**Libraries** — [libfixmath](https://en.wikipedia.org/wiki/Libfixmath) (C, Q16.16 only: `fix16_sqrt/exp/sin` via shift-subtract sqrt + polynomial sin) and [fpm](https://mikelankamp.github.io/fpm/) (C++ header-only, full `<math.h>` surface over integers). Read them for the *algorithms* (quarter-wave sine symmetry, shift-and-subtract isqrt), not the format — Q16.16 is the wrong point in JS (see §6: Q16 squared distances exceed 2⁵³). Shipped-game pow-curve practice is uniformly: **small baked LUT (+ lerp when the input is continuous), or redesign the curve to a rational one** — nobody ships a general fixed-point `pow` in a hot path.

**The JS-specific determinism boundary (load-bearing fact):** ECMA-262 requires `+ − × / %` and **`Math.sqrt`** to be IEEE-754 correctly rounded — bit-identical across engines. The spec's *implementation-approximated* list — `sin, cos, pow, exp, log, atan2, hypot, …` — is explicitly allowed to differ per engine. So the census's Math.pow/sin/hypot inventory is precisely the illegal-instruction list, `Math.hypot` included, while `Math.sqrt` is legally deterministic and usable as an isqrt accelerator (§3). Sub-2⁵³ integer arithmetic in plain Numbers is *exact*, not merely deterministic ([MDN safe integers; ECMA-262 Math object notes](https://developer.mozilla.org/docs/Web/JavaScript/Reference/Global_Objects/Int32Array)).

## 3. ARITHMETIC CONTRACT (rounding IS behavior)

- **ONE core rule: floor toward −∞** (`>>` / `Math.floor`) at every fixed-point rescale, everywhere in the sim. Precedent: Doom's `FixedMul` truncates; libfixmath defaults likewise. **Banker's rejected**: its only virtue is statistical bias cancellation, worthless under a one-time re-baseline, and it's a branch plus a rule people misremember.
- **Round-half-up exists only at named unit boundaries**, each a single named function: `centsFromLegacyFloat()` (save migration), `tipToCents()` (milli-cent → cent at `payTip` entry), build-time constant baking. Matches legacy `Math.round` on the positive domain.
- **Exact division idiom**: for nonneg exact ints, `(a - a % b) / b` is the *true* quotient exactly (JS `%` is fmod — always exact; the final divide is an exact integer). `Math.floor(a/b)` is also cross-engine deterministic (correctly-rounded divide) but can differ from the true floor by 1 near ulp boundaries — pick the exact idiom in the core so proofs stay rational.
- **isqrt** (needed for `stepTo`/`collide` magnitudes): `s = Math.floor(Math.sqrt(n)); while (s*s > n) s--; while ((s+1)*(s+1) <= n) s++;` — legal because `Math.sqrt` is correctly rounded per spec; the fixup makes it exact-by-construction regardless. (Pure-integer fallback: libfixmath-style shift-and-subtract.) Normalization multiplies before dividing: `dx_q8 * step_q8` then divide by `d_q8` (≤ 4.2×10¹⁰, exact).
- **Threshold compares**: never divide to compare — cross-multiply (`darkness() > 0.7` ⇔ `10*num > 7*den`); ratios like `patience < maxPatience*0.5` ⇔ `2*patience_q < maxPatience_q`.

## 5. RNG

- **Keep mulberry32 verbatim** (`Math.imul`-based, already exact-integer). Replace simlib's `Object.create(Math)` proxy swap with an explicit sim-RNG object threaded to consumers — numerically inert if call order is preserved; `crabs.js` already takes an injectable `rng`.
- **Boundary idiom — stop minting 0..1 doubles.** Draw the raw u32; bounded int in [0,n): `(u32 * n) / 4294967296 | 0` — for n ≤ 2²¹ the product is < 2⁵³ (exact), /2³² is a power-of-two scale (exact), floor exact → a fully exact multiply-shift. This is the Knuth/[Lemire](https://lemire.me/blog/2019/06/06/nearly-divisionless-random-integer-generation-on-various-systems/) construction *minus* the rejection step: residual bias ≤ n/2³² < 5×10⁻⁴ ppm for every range in the game (quip picks, purse `3200 + bounded(4401)` cents, ferry counts, tick durations `280 + bounded(360)`) — accept it; add Lemire rejection only if a future draw needs cryptographic-grade uniformity (none does). **Avoid `% n`** (bias concentrated + low-bits superstition).
- **The slice-safety invariant**: mulberry32 consumes exactly one state advance per `Math.random()` call today. Every converted site must consume **exactly one u32** where it consumed one double — then the stream position is bit-identical and *unconverted* downstream sites (illness rolls, hire rolls, `ferryBatch`, `visNeeds`) are untouched. This is what makes the strangler sliceable at all. Ranged doubles (`14+rand*18`, `32+rand*44`) are single draws → single bounded-int draws; the value distribution shifts by the quantization grain → that slice's scheduled re-baseline.
- **Do not split cosmetic/decision streams per slice.** The interleave (quip text, `animT` seeds, wander spots between illness rolls) means a split re-baselines everything downstream at once and destroys slice-by-slice referee comparisons. Splitting is a final-rung task, justified only if browser/headless stream parity ever becomes a goal (browser-only draws — title wander, `pickTrack` — currently desync the browser stream from headless anyway).

## 6. JS ENGINE NOTES

- **Smi boundary**: V8 stores small ints inline ([Smi tagging](https://medium.com/fhinkel/v8-internals-how-small-is-a-small-integer-e0badc18b6da)); payload is 32-bit on plain 64-bit builds (±2³¹) but **31-bit under pointer compression — Chrome's default — i.e. ±2³⁰**. Out-of-range numbers become heap-allocated HeapNumbers with real GC cost ([mutable heap numbers](https://v8.dev/blog/mutable-heap-number), [React performance cliff](https://v8.dev/blog/react-cliff)). Design stored state to ±2³⁰ (the format table complies everywhere). **Answering the prompt's check**: Q16.16 positions (2512·2¹⁶ = 1.65×10⁸) actually *fit* Smi — the true Q16.16 killer is squared distances (2.7×10¹⁶ > 2⁵³ → inexact compares). Q8 keeps positions at 20 bits and dx²+dy² exact at ≤ 8.3×10¹¹.
- **Int32Array-backed flat state** sidesteps Smi entirely: storage is raw int32; reads let the JIT speculate int32 ([asm.js heritage](https://en.wikipedia.org/wiki/Asm.js), [`|0` coercion semantics](https://2ality.com/2013/02/asm-js.html)). The `x|0` / `>>>0` idioms remain the way to keep values in the int32 domain the optimizer sees. `Math.imul` is required only for **mod-2³² wrap semantics** (mulberry32, `mistPeak` day-hash — both already correct); plain `a*b` is exact and fast whenever the true product < 2⁵³ — use it for everything else.
- **BigInt: no.** Still roughly an order slower than Number arithmetic with allocation per op, and V8 states it is "not particularly optimized" ([v8.dev/blog/bigint](https://v8.dev/blog/bigint), [comparison](https://www.webdevtutor.net/blog/javascript-bigint-vs-number-performance)). Unnecessary: every intermediate in the design is < 2⁵³ by construction (the format table's headroom column is the proof obligation — keep it in the design doc and check any new formula against it).
- Determinism ledger (from §1): `+ − × / % sqrt` on exact ints = exact everywhere; correctly-rounded-but-inexact double ops = still cross-engine deterministic; `pow/sin/cos/exp/log/hypot/random` = implementation-approximated, **banned from the core** (LUTs/rationals only). At ~14 actors the perf stakes are small; the representation is for bit-identity and the WASM/GPU rungs, not speed.

## 7. FIVE RISKIEST DESIGN DECISIONS

1. **Money must land as ONE atomic slice, bending the strangler's one-subsystem rhythm.** `worldMoney()` sums *every* balance; a half-cents/half-float world can't produce an exact audit, so either build a transitional dual-mode audit (float tolerance until the last money site converts — weeks of a referee that can't say "exact") or convert all balances + tip/OT/fund paths + save migration in one slice. **Recommendation: one atomic money slice, audit flips to `=== 0` the same day; it's the single highest-value exactness win and the audit itself is the safety net.**
2. **Movement isqrt/normalization rounding = the biggest re-baseline blast radius.** LSB choices in `stepTo`/`collide` perturb every trajectory; congestion is load-bearing gameplay (BOUNCE_BUDGET, warps, SHUN geometry, cabana lanes). **Recommendation: floor-everywhere per §3, convert the whole `stepTo`/`collide`/`giveBerth`/`updateStuck` cluster in a single slice** (mixed float/int collision partners double the churn), and referee on `_stats.warps`, seat declines, and the eviction median — this is the slice where "same feel" is argued from the matrix, not the diff.
3. **Shimmer stride 2048 (exact-mean, period +1.9%) vs 2086 (faithful period, statistical mean).** The design comment stakes eviction fairness on mean-preservation. **Recommendation: 2048 + odd-symmetric LUT — provable exact zero mean beats an imperceptible 30 ms period shift; run the matrix with `_noShimmer` as the A/B control and watch the 0/16 floor.** Flagged as an intentional feel-adjacent redesign.
4. **Browser tick quantization.** The int core makes headless bit-exact for free, but the browser must consume wall time via a remainder accumulator in whole 50 ms ticks (clamped catch-up at FF speeds) — dropping the browser sim from ~60 Hz integration to 20 Hz. The headless-only fingerprint is *blind to this by construction*. **Recommendation: classic fixed-timestep with render-side position interpolation between ticks (Gaffer-style "fix your timestep"); explicit human play-testing gate, because no automated referee covers it.**
5. **Integer quantization manufactures ties that floats made vanishingly rare.** JS sort is spec-stable (Factorio's map-gen desync was exactly an [ambiguous comparator](https://wiki.factorio.com/Desynchronization)), so the danger isn't comparator UB — it's that `errandScore`'s first-wins `s > bestScore` and the no-tie-break OT-tired and shelter-wallet sorts start hitting *equal* int keys constantly, making candidate/insertion order load-bearing behavior. **Recommendation: every slice that quantizes a sort/argmax key must add an explicit deterministic tie-break (persona index / `qSeq`) in the same slice, as part of the slice contract.**
