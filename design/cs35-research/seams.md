## 1. TICK / FRAME LOOP
- Single `function frame(now)` (~15459) on `requestAnimationFrame`; boot at file bottom: `initNpcs(); migrateLegacy(); load(); requestAnimationFrame(frame)` (~16144–16160). `window.cheat(n)` console hook.
- **Two clocks**: `raw` = wall dt (clamped 0.1s, drives hire-card only), `dt = raw * TURBO * (ffSleep?6:FF_SPEED[ffMode])` = sim seconds. `time += dt`. Sim minutes: `tmin += dt * TS` where `TS = 4` game-min/real-sec (~3996). `day`/`tmin` are the calendar; `weekdayIdx(d)=(d-1)%7`, WEEKDAYS MON..SUN, `POLL_WEEKDAY=6` (Sunday).
- **Midnight rollover** inline in frame (~15489): `tmin -= 1440; day++`, then `settleFishMarket()`, rep mean-reversion, per-crab day-ledger reset, `trade.day` reset, `today = newDayLog()`.
- **Nightly settlement at 20:00** (`tmin >= 20*60 && lastRentDay !== day`, ~15501): a hard-ordered pipeline, the game's real "phase list": (1) back pay, then wages with rent reserved first; (2) house rents/evictions per crab; NPC-owner payrolls; `runWageRelations()`; **`runTownHall()`** (levy/purse collection, shelter rent remit, pot stocking — placed before landlord rent deliberately); per-NPC-biz `settleCreditLine` + strikes + `runHoursPolicy(b)` + `runWagePolicy(b)`; `runSuccession()`; `runRivalAmbition()`; `runHotelier()`; `runAccommodation()`; (2.5) epidemiology (illness roll, cure/death via CARE_LANES); (2.6) boredom walkouts; `runLaborPolicy(b)`; (3) player rent + `settleCreditLine` → nightly `report` card + `departBuild()`, `save()`; failure → `gameOver/bankrupt`.
- **Per-frame system order** (~15867): `updateBus` → `runJobBoard` (once at 7:30) → `updatePoll` → `updateCustomers` → `runChatter` → per-crab: `updateSchedule(c)` then dispatch **on `c.dayState`**: `chat`(preempts all)/`toWork|toHome`→`updateCommute` /`toErrand|errand`→`updateErrand` /`atTap`/`atBall`/`selfCook`/`working`→(`updateFishing`|`updateKitchen`)/`directed`→`updateDirected`/`home`→`updateHome`; then `updateStuck`, `maybeQuip` → `collide(dt)` → **`if (window._headless) return` before any draw** (~15917). Autosave every 5s (`saveT`), plus `visibilitychange`/`beforeunload`.
- Speed: FF_SPEED [1,2,3,6]; `ffSleep` sun-skip chains 6 extra synchronous `frame()` calls per real frame (~16134). `?turbo=N` query multiplies dt.

## 2. ACTOR MODEL
- Three populations: `crabs` (player crew), `npcs` (townsfolk incl. owner crabs SUDSY/REEF, fishers, drifters), `customers` (tourists + multi-day `visitor`s). `allCrabs() = crabs.concat(npcs)`. `floaters` = FX.
- **Crab = { p: persona, ...transient }** (`newCrab` ~5742): persona `p` is the SAVED identity (name, trait, mode, acc, color, shift M/E/D, job, wallet, house/boat/homeless, hunger/thirst/dirt/bored/tired, sick{days}, owner-id, wage/wageOwner/gripe/walkout, ot/sickPol/restT, owed, made{dishId:count}, log). Everything else is transient and rebuilt: x/y/tx/ty, `dayState`, `cstate` (commute), `kstate` (kitchen: idle/walk/toSlot/work/toBus/toSink/toStallClean/cleaningStall), duty, pendingOff, order, wander/chat/nap/quip fields. **The save persists personas only; behaviour state is derived** — the load contract is "put them back on the promenade and let the machine re-decide".
- **Top-level dayStates**: home, toWork, toHome, working, toErrand, errand, atTap, atBall, selfCook, chat, directed. `updateSchedule` (~7252) is the dispatcher: commute at `leaveGmin`, shift end → `pendingOff` → after-shift errand chain, sick-day/off-day gates, fisher self-employment breaks.
- **Errands = the action system** (~7424–7659): `pickErrand(c)` gathers candidate stops as small data records — `{biz, recipe, need}`, `{tap:i, need, appeal}`, `{soup:true}`, `{ball:true}`, `{vote:true, poll:i}`, `{selfCook:true, recipe}` — then scores each with `errandScore` = appeal × (ERRAND_RANK[need] + level) / (1 + detour/400), DIRE≥0.9 ignores geography. **Adding a new "go do X" today = add a `take({...})` block in pickErrand + a start/update pair + a branch in `errandStopX`/`beginErrand`/frame dispatch.** This is the single biggest hard-coded surface a cultureway runtime must open up (voting is literally an errand with rank 2).
- **Direct orders**: `orderCrab(c,wx,wy)` (~8276) right-click semantics: workplace→clock-in, home→knock off, business span→`forcedErrand` (pickErrand's gates minus thresholds), else `orderGoto`. `abortActivity(c)` (~8209) is the universal cleanup: releases station slot, claimed customer, stall, queue ghost, chat, bus; parks in `dayState:"home"` as the known-safe state. Every refusal pops text — never silent.
- **Visitors**: minted by ferry batches (4 sailings/day, rep-driven load), own needs dict + wallet ("minted purse", destroyed on departure), states VIS_STATES (ashore/roam/toBiz/toRoom/inRoom/onSand/toPier), a stay-ledger (`stayOf`) that feeds the departure card, own diary. Tourists can be converted to hires (`convertTourist`).
- **NPC owners**: `OWNERS` registry (~563) + per-lease CPU policies run at settlement (HOURS_POLICY, WAGE_POLICY, LABOR, rival state machine RIVAL_STAGES none/eyeing/offer/compete/done, hotelier, dorm/annexe mayors). Owner AI = "one move a night, convergent rules" pattern, all persisted as small `{cd,hist,...}` blobs.

## 3. ECONOMY
- **Accounts**: player `coins`; each crab `p.wallet`; each visitor `wallet`; owner tills — and the **one-wallet rule**: `defineTill` (~536) makes `OWNERS[k].till` a getter/setter that settles onto the owner's living crab's wallet (`_held` is only backing for ownerless leases). `townFund.bal` (the hall), `credit.bal` (player debt) + per-owner credit.
- **Uniform account handle**: `acctBal/acctMove/acctName/bizAcct` (~979) over `{k:"player"|"owner"|"crab"|"vis"}` — an existing, small, generic money-movement primitive layer.
- **Business flow**: `creditBiz(b,amt,x,y,quiet)` / `debitBiz` (~601) route to owner till or coins + day book (`bizDayBook`). `fundTake(account, amt, why)` / `fundPay(biz,...)` / `fundRemit(amt,...)` (~1040–1081) are the hall's ONLY three doors; every row goes to `townFund.ledger` (capped 48, saved last 24).
- **Conservation is PROVED, not promised**: `worldMoney()` (~1007) sums every wallet/till/fund minus debt; `auditFund` (gated on `window._auditFund`) snapshots world money either side of every fund movement; the suite asserts delta==0 for take/pay and ==−amt for remit ("the fund moves money and never mints it"). Visitor wallets are explicitly minted-and-destroyed; imports leave via `trade`; Mr. Pincherton (landlord) is the world's money sink (rents are destroyed).
- **Prices/wages as data**: BIZ recipes carry `pay`; `priceMul` per biz (0.7–1.3, 5% steps), locals pay +25%, PRICE_ELAST; per-biz `wage` + per-crab private deals; the elected **wage floor** (`WAGE_FLOOR.steps`) and **head cap** (`HEAD_CAP.steps`) are step-table policies; PURSES table (~702) — levy/dues/rents/tin, each `{name, unit, who, steps[5]}` — the funding mechanisms are already data.
- Imports: `IMPORTS`/`tradeImport`/`INGREDIENT_COST`, fish market `settleFishMarket` (price FISH_FLOOR 2..FISH_IMPORT 7).

## 4. THE SAVE (read fully)
- Keys: `SAVE_KEY "crabshack3_v1"` = legacy single-slot, migration source only (`migrateLegacy` → slot 1, ~6194). Live keys `crabshack3_v1_s1..s5` + `_active`. `SAVE_VER = 1`; `env._ver` written; `saveProblem` rejects `_ver > SAVE_VER` ("FROM A NEWER CRAB SHACK").
- **`saveProblem(s)`** (~6098) is the single gate for stored/migrated/imported blobs; deliberately minimal: object, ver, non-empty `personas[]` with string names, finite day/coins. "Nothing in the game may be mutated before this says yes."
- **Top-level schema of `save()`** (~6205): `coins, lifetime, lv{upKey:lvl}, day, tmin, lastRentDay, gameOver, memorials[], rep, townCatch, t(Date.now), bankrupt, credit{bal,warned}, won, winRec, _oneWallet:1, dayLog[-6:], personas[] (crabs.map(c=>c.p) — WHOLESALE), npc{tills, credit, personas[]}, owners{id:{name,till,credit,darkT,soft}}, bizOwner{}, bizBought{}, market, bizTake, bizStrike, fund{bal,bowls,strikes,shut,arrears,served,cold,wasted,ledger[-24:]}, hall{mayor,policy,termDay,poll,stand,nominee,plat}, box (ballotBox — real paper is a resource), dorm, annexe{built:COUNT}, board(jobBoard), hireDay, trade, sudsRefund, firstPour, musicOn, musNudges, dayOpen, helpSeen, hours{biz:[open,close]}, mealPol{}, tipShare{}, price{}, rival, hotelier, hoursPol, visitors[] (short-key records n/c/a/x/y/s/w/p/... + st stay-ledger + log), ferry{t,sail,d}, _vis:1, wage{}, wagePol, sickPol{}, autoLabor{}, laborPol` + `_ver`, `_meta` (=`slotMeta(env)` preview card, re-derivable).
- **Migration style = flags + defaulting, not version numbers**: `_oneWallet` (till/pocket merge), `_vis` (pre-ferry saves get `seedVisitors()` at boot, guard at ~16159, NOT in load), `sudsRefund` (removed-laundromat refund paid once), stale-field drops in `newCrab` (`sandy`→`tired`, `homeX`), removed-business jobs → shack/pier. Absent key = founding behaviour ("the defaults above ARE the old world").
- **`load()`** (~6325) clamps EVERYTHING — "a save is an untrusted file (the importer exists)": every number `Math.max/min`-banded, strings `.slice(0,n)`, enums checked against live tables (`PURSES[mech]`, `MEAL_POLS.includes`, `ACC_KEYS`), ballot papers can't exceed printed−cast ("a reload does not conjure paper"), setters (`setBizHours/setBizWage/setBizPrice/setTipShare`) re-clamp. Ordering constraints inside load: owners before personas; dorm/annexe before visitors (rooms re-linked BY INDEX); dead NPCs stay dead (saved persona list is the roll of the living); `seatFoundingMayor()` last. No offline earnings by owner ruling.
- **Export/import**: `exportSlot` downloads the RAW localStorage string as `crabshack3-slotN-dayD-stamp.json` via Blob+anchor; `importJson` = parse + `saveProblem` only, `pendingImport` staged, `commitImport(i)` writes the envelope UNTOUCHED into a slot so load()'s migrations run on it identically. Hidden `<input id="importSave">` in index.html is the upload surface.
- **Measured size** (I ran simlib, seed 1337 fresh): day 4 = **18.6 KB**, day 8 = **28.1 KB** (baseline town went bankrupt day 8, as designed). Top keys: `npc` ≈ 7.5–12K, `personas` 3.5–4.5K, `visitors` 3.3–5.2K, `fund` ~1–1.7K, `box` ~1K. Diaries dominate personas (LOG_MAX 40 × ≤39-char 4-array entries; visitors 24). So current saves are tens of KB; localStorage headroom (~5MB) leaves ~2 orders of magnitude for cultureway payload; the brief says "the file may be big".

## 5. DETERMINISM
- **No in-game seeded RNG.** game.js calls bare `Math.random()` everywhere (~hundreds of sites) and `Date.now()` only via `nowMs()` (save timestamp, try/caught for headless). Determinism is imposed FROM OUTSIDE: `tools/simlib.mjs` runs the five real game files in a Node `vm` context whose sandbox `Math` is `Object.create(Math)` with `random = mulberry32(seed)`, `performance.now` = synthetic `simNow`, canvas/audio stubbed, localStorage = Map, and keeps every registered event listener so `sim.tap(x,y)` drives the REAL click handlers. `window._headless` skips all rendering inside frame.
- CLAUDE.md contract: **simlib executes the real engine; never fork game logic in tools/**; `runDays(N)` is absolute; any new browser API used by game.js must be stubbed or the toolchain breaks.
- `tools/headless.mjs`: seed-matrix balance harness (`--days --seeds --jobs --buy --set --wage --star`), arm-off hatches all read-only `window._no*`/`window._failOff` flags the game reads but never sets (`--nohall --nofloor --nocap --norival --nohotelier --nodorm --noannexe --failoff wander,chat,...`). `tools/suite.mjs`: 230+ assertion scenarios (43 `name:` markers in head region alone... file registers via `scenario(name, fn)`), includes stuck-detector over `(dayState,kstate,cstate,x,y)` tuples and the fund-audit scenario. Instrumentation seams: `window._stats` (rows, never behaviour), `window._auditFund`, `window.dayLog`; diary explicitly consumes **no RNG** and is behaviour-neutral (rule 4 at ~10130), and `_stats.rollLog` "consumes no RNG, so a build with it on is behaviour-identical".
- **Constraint on save-resident logic**: cultureway code must (a) get all randomness through the context's `Math.random` (so the seed harness governs it), (b) never touch wall clock/Date/performance directly, (c) consume no RNG when disabled/observing (the house rule for optional systems), (d) be loadable inside the vm sandbox (no DOM beyond the stubs, no fetch/import), (e) keep frozen fingerprints stable — the suite pins day-2 behaviour byte-for-byte in places.

## 6. RENDERING / UI
- `ppu.js`: 256×240 (288 portrait; H decided pre-parse by `window.SCREEN_H`, rotate = page reload) canvas, SNES 15-bit quantized `rgb`, `parseArt(rows, palette)` — sprites are **character maps**: arrays of equal-length strings + `{char:[r,g,b]}` palette, '.' transparent, pre-baked mirror; `blit/tintArt/rect/px`; two bitmap fonts: 5×7 `text/textShadow/textWidth` (6px pitch) and 3×5 `smallText/smallTextWidth` (4px pitch), glyph canvases cached per color.
- game.js wraps with world-space `wblit/wrect` (camX-relative) and text fitters `fitSmall/fitText` (~445): pixel-measured truncation with `..` — the house rule for any string on a card.
- Frame paint order (~15918): `drawBG/drawTown/drawBus` → **painter's list**: stations, tables, stalls (hotel rooms are stalls with `lodging`), customers, crabs, landlord, beach ball, each `{base:y, f}` sorted by baseline → signs, floaters → night wash → nav/HUD chips → **reading surfaces own the screen** (report/depart/manage/dossier/save/help layered with explicit mutual-exclusion booleans; toasts wait).
- **The card pattern** (the UI "registry" such as it is): each surface is a triple of functions — `xxxRects()` returning a dict of named `{x,y,w,h}` hit boxes (`manageRects` ~13411, `navRects`, `saveRects`, `dossierRects`, `cyclerRects`, `helpRects`), a `drawXxx()` that renders from the same rects, and tap routing inside the big `cv.addEventListener("click")` handler (~10498) plus panel tab zones (tab = "crew"/"shop"/"menu"). Layout is hand-placed constants; panel geometry derives from `TALL` (portrait). **There is no declarative card/list engine — a data-driven culture UI would either target the rect-dict pattern (generate rects+rows from data, as drawHall/drawReport already half-do with line arrays) or need a small new list/card renderer.** Precedent for data-driven text surfaces: report/depart cards are built as arrays of fitted lines; UP_HELP tooltips are string tables governed by the ruling "a tooltip may state machine facts, never profitability".
- `merge.js` shows the plug-in shape already used once: self-contained IIFE, game.js calls `MergeMode.frame(dt)` and gives touch handlers first refusal.

## 7. EXISTING DATA-DRIVEN-NESS (house style)
- **`BIZ` table** (~142) is the crown jewel: a business is one object — name/sign/kind, rent, owner, x-span/door, `stations{kind:[{x,y}]}`, `tables[]`/`stalls[]` (+`lodging`, `sellable` flags grow behaviour: "any business that carries `sellable` grows an OFFER chip"), `source/out/queueX/park/rack`, `recipes[{id, icon, pay, raw(+raw2), steps:[[station, secs, artifact]], showerT, deep}]`. The kitchen engine interprets recipes generically; the hotel is proof the abstraction holds ("a business whose dish is A NIGHT'S STAY"; rooms reuse the stall occupy/clean cycle).
- `crabs.js`: TRAITS (move/work/tip multipliers + quip tables + flags like `pauses`, `lateMin`), MODES, FOUNDERS, SHIFTS, name pools — pure data + one factory taking an injectable rng.
- `sprites.js`: all art as character maps over a shared PAL with `swap()` recoloring — art is data and diffable.
- Policy/econ tables: PURSES, WAGE_FLOOR.steps, HEAD_CAP.steps, CARE_LANES, IMPORTS, INGREDIENT_COST, UPS catalog (base/mult/max/lvl + UP_HELP strings), TOURIST_PULL, VIS_RATE/WANT/RANK, HOURS_POLICY/WAGE_POLICY/LABOR_CFG/RIVAL_CFG/HOTELIER_CFG/DORM_CFG/ROOM_CFG/SALE_CFG/CREDIT_CFG config blobs, WANDER_SPOTS, POLL_PLACES, LOG_CATS. Constants carry measured rationales inline; numbers are rulings.
- Diary entry format `[day, minute, cat, line]` chosen for save-byte economy (arrays ~40% smaller than keyed objects) — the house standard for save-resident row data.

## THE SEAMS (where a cultureway loader/interpreter could hook)
1. **The settlement pipeline** (20:00 block in frame): already a linear sequence of named `runX()` phases (`runTownHall`, `runSuccession`, `runRivalAmbition`, `runHotelier`, `runAccommodation`, per-biz policy runners). A phase list `[fn,...]` is one refactor away; the Crabocracy IS mostly this block plus the poll subsystem — the natural unit to lift into data.
2. **The errand candidate list** (`pickErrand`'s `take({...})` records + `errandStopX` + `startX/updateX` pairs + frame's dayState dispatch): a registry of `{id, when(c), stop(c), start(c), update(c,dt), need, rank, appeal}` would absorb tap/ball/soup/vote/chat wholesale — voting already lives here as data-shaped records. This is the "new activity" seam.
3. **Money primitives**: `acctBal/acctMove/bizAcct` + `creditBiz/debitBiz` + the fund's three doors (`fundTake/fundPay/fundRemit`) + `worldMoney`/`auditFund`. A cultureway's institutions can be expressed entirely in these verbs and inherit the conservation proof for free — the audit harness already asserts arbitrary movement sets.
4. **Policy-as-step-tables**: PURSES/WAGE_FLOOR/HEAD_CAP show the shape: `{name, unit, who, steps[]}` + a `stake(c, p)` valuation function per dial (capStake/wageStake/purseCost feed `platValue`→`voteReason`→`pickCandidate`). A cultureway's levers slot here if valuation fns can be supplied.
5. **The save envelope**: top-level namespace is open (unknown keys are ignored by load — forward-compatible by construction); `_meta` derivation, `saveProblem` gate, and the flag-based-migration idiom give a ready extension point: a `cultureway:{...}` key with its own clamp-on-load discipline. Import path runs the same gate, so save-resident content already flows through one validated door.
6. **UI rect-dict card pattern** + fitSmall/smallText + the line-array report style: a declarative card spec (rows of fitted lines + named hit rects) matches existing structure closely enough to generate.
7. **The vm sandbox** (simlib): proof the whole engine runs under injected globals — a cultureway interpreter that lives in the same context needs only the same stubs, and the suite/matrix can regression-test cultureways exactly as they test the Crabocracy (arm-off flags are the precedent for per-institution toggles: `window._noHall` already runs the town "cultureway off").
8. **`window._failOff` / `_no*` / `_stats` hooks**: the established read-only config-injection channel — the loader can adopt the same "game reads, never sets" contract.

## THE HAZARDS (what makes code-in-save hard)
1. **~1000 top-level globals in one shared script scope**: `coins, day, tmin, crabs, npcs, customers, BIZ, OWNERS, UPS, hall, townFund, ballotBox, trade, market, rival, hotelier...` — mutable module state everywhere; no namespace; a save-resident interpreter must be handed a curated API surface or it needs the whole global soup.
2. **Layout constants frozen at parse time** (`H`, TALL, CARD, PANEL_Y... derived once; rotate literally reloads the page). BIZ coordinates, HOUSE_XS, POLL_PLACES, WATER_TAPS, lanes y=146/168, solid-band caches (`_bands`, `_bandsKey`) — geometry is compile-time data with sim semantics (travel lanes, queue slots) baked into comments and magic y's; a culture that moves buildings collides with the collision/lane system's assumptions.
3. **Live object cross-references**: chefs hold `cust`, customers hold `table/recipe/biz/server`, stalls hold `occupant`, visitors' rooms re-linked by index at load; save already refuses to serialize mid-pipeline states (VIS_SAVE_STATES whitelist, "anybody in a line is put back on the promenade"). Any save-resident actor logic must respect the same "no live refs cross the save boundary" rule.
4. **Closures with hidden state**: `defineTill`'s `held` closure + property getters (till is an accessor, `_held` non-enumerable — naive JSON of OWNERS would double-count or drop money); memo caches (`_cardCache`, `_cotRoll`, `_offMap` with stamp keys); `today` day-log rebuilt nightly.
5. **Behaviour spread across call sites, not tables**: the Crabocracy is ~1500 lines woven through constants 655–1870 + updatePoll/castVote/printBallots/declarePoll + pickErrand's vote block + settlement's runTownHall + drawPollingPlaces/drawHall — hard-coded strings ("MAYOR", top hat), thresholds, and measured constants each carrying an owner ruling. Extraction must carry the rulings (conservation, local-remit-only, paper-is-a-resource) as invariants, not just the code.
6. **Determinism is environmental**: bare `Math.random` means any cultureway code executed OUTSIDE the vm context (e.g. a Function constructed from save text in the browser vs harness) still inherits seeding only if it calls the context's Math; `eval`/`new Function` in the vm context works but CSP in some hosts may not allow it in-browser; ordering of RNG draws is part of the fingerprint — inserting one extra `Math.random()` call shifts every seed (the suite's frozen fingerprints will catch, and complain about, everything).
7. **The suite pins today's behaviour**: 230 scenarios + frozen fingerprints + the 16-seed matrix floor mean the refactor to a pluggable runtime must be behaviour-identical with the Crabocracy loaded — the "consumes no RNG when off" discipline (see _stats.rollLog note) is the proven template.
8. **saveProblem is minimal by design** — it validates personas/day/coins only; load()'s safety is clamp-per-field written by hand per key. A cultureway blob needs its own clamp layer of the same rigor, or hand-edited saves become an injection surface (the game explicitly treats saves as untrusted input, but "untrusted" today means bad numbers, not hostile code).
9. **Concurrent-edit reality**: game.js changed under me mid-survey (agent fleet active; see memory "Agent fleet merge discipline", and frame() contains merge-scar comments like the pause-removal ReferenceError note at ~15472). Line refs decay fast; anchor on names, not numbers.
