# WHERE SHIPPED GAMES DRAW THE DATA/CODE LINE — culture & government as data

Raw research for synthesis. All claims sourced; confidence flagged where a source was thin.

---

## 1. RimWorld: Ideology DLC (ideoligions)

**What an ideoligion is made of.** Structure (e.g. Theist/Animist/Collectivist), 1–4 **memes** (big ideas), **precepts** answering ~19 fixed "issues" every ideoligion must answer (each issue is an `IssueDef`; a precept is a `PreceptDef` choosing a stance), plus rituals, roles (specialist positions like Moral Guide), venerated animals, relics, ideo-specific buildings/apparel/styles.

**The data format.** Everything is a `Def` — XML records deserialized into C# classes (`PreceptDef`, `MemeDef`, `IssueDef`, `RitualPatternDef`, `RitualBehaviorDef`…). A `PreceptDef` carries `defName, label, issue, impact, requiredMemes/conflictingMemes, displayOrderInImpact` and — the crucial part — a **`comps` list**: each comp is an XML element whose `Class=` attribute names a C# `PreceptComp` subclass (e.g. self-took-memory-thought, knows-memory-thought, situational thought, unwilling-to-do) with XML-tunable fields. So a precept is *configuration over a fixed menu of code-implemented behavior atoms*. Defs docs: https://rimworldwiki.com/wiki/Modding_Tutorials/Def_classes , https://rimworldwiki.com/wiki/Modding_Tutorials/XML_Defs , auto-generated def-XML docs: https://github.com/Epicguru/Rimworld-Auto-Documentation , https://rimworld.lattemacchiato.dev/

**Data/code line.** Pure XML can: add new precepts/memes that recombine existing comps, thoughts (via `ThoughtDef` + `ThoughtWorker` classes that already exist), rituals from existing ritual behaviors/outcomes. Genuinely **new behavior** (e.g. "pawns get thoughts about alcohol consumption they *observe*", tracking state the engine doesn't already track) requires a C# assembly and usually Harmony patches — every serious precept mod ships `Assemblies/` + `Source/` next to `Defs/`: "Ideology: More Precepts" https://steamcommunity.com/sharedfiles/filedetails/?id=2559533848 (repo: https://github.com/llunak/rimworld-moreprecepts , forum: https://ludeon.com/forums/index.php?topic=55241.0 ), "Precepts++" https://steamcommunity.com/sharedfiles/filedetails/?id=2605184998 . The community even built a framework whose whole point is widening what XML alone can express: "New and Improved XML comps" https://steamcommunity.com/sharedfiles/filedetails/?id=3300761548 . Pain point: even UI toggles on the ideology edit screen needed Harmony ("Persistent Precepts" https://github.com/Alleykatz/PersistentPrecepts ).

**Save-file relationship (highly relevant to CS3.5).** `PreceptDef`s etc. live in game/mod XML, but each game's **ideoligion instances live in the save file as plain XML** — the fluid-ideoligion save conversion guide has players text-editing their save to flip an ideoligion to fluid and gain development points: https://rimworldwiki.com/wiki/Fluid_ideoligion_save_conversion_guide . Ideoligions are also exportable/importable as standalone preset files (base game partially; fully via mods like Save/Load Ideos https://steamcommunity.com/sharedfiles/filedetails/?id=2554353736 , player discussion: https://steamcommunity.com/app/294100/discussions/0/4354495152403617862/ ). So RimWorld splits: **choice-instance data in save; vocabulary + behavior atoms in mods/engine.** A save referencing removed mod defs degrades/breaks.

## 2. Crusader Kings 3: cultures, traditions, governments (Paradox/Jomini script)

**Culture as data.** Post-1.5, a culture = **pillars** (ethos, heritage, language, martial custom) + up to N **traditions**, all defined in `common/culture/` script files. A tradition block: `type`, `parameters` (arbitrary named flags like `martial_custom_male_only_combatant = yes`), `culture_modifier` / `character_modifier` / `county_modifier`, `can_pick` trigger, cost, `ai_will_do`. Example seen in the wild: `martial_custom_male_only = { type = martial_custom parameters = {...} culture_modifier = { culture_tradition_max_add = 100 } can_pick = { is_ai = no } }`. Sources: https://ck3.paradoxwikis.com/Culture_modding , https://ck3.paradoxwikis.com/Culture , tradition modding thread: https://forum.paradoxplaza.com/forum/threads/modding-for-cultural-traditions.1511331/ , 1.5 buildings gained culture-parameter-conditional modifiers: https://www.paradoxinteractive.com/games/crusader-kings-iii/news/dev-diary-87-royal-modding . **Parameters are the interesting mechanism**: a tradition asserts named flags; other script (and some engine systems) *query* those flags — a publish/subscribe vocabulary decoupling "what this culture believes" from "what checks it."

**The script language.** Declarative `x = { y = z }` DSL: **triggers** (pure predicates), **effects** (mutations), **scopes** (current entity + scope-chaining like `primary_heir.faith.religious_head`), **scripted_effects/scripted_triggers** (textual macro templates with `$param$` substitution — pasted, not called), **script_values** (calculations, recomputed on demand), **on_actions** (engine lifecycle hooks that fire script), events. Explicitly **not Turing-complete**: no string manipulation, no inline math beyond script_values, 1D arrays only, ~1000-iteration loop cap, "slower than actual game code," no OS access. Variables (scope-local, global, temporary, dead-character) **do persist into saves**. Source: https://ck3.paradoxwikis.com/Scripting

**Hardcoded remainder.** "Most of AI or army behavior is done in game code, inaccessible to modders." UI is a separate GUI system (scripted GUIs as a workaround). Culture-reform pacing and the 50-year cooldown are hardcoded; script can't create parentless cultures from nothing at runtime (mods lean on the native divergence/hybridization systems instead): https://ck3.paradoxwikis.com/Scripting , https://steamcommunity.com/sharedfiles/filedetails/?id=3735274450 . **Governments** (`common/governments`) are thinner data than cultures: mostly flags + which laws/vassal-contract options apply (tax/levy/rights options are scriptable: https://ck3.paradoxwikis.com/index.php?title=Governments_modding&veaction=edit&mobileaction=toggle_view_desktop , https://ck3.paradoxwikis.com/Government ); the deep mechanics behind a government type are engine code keyed off those flags — which is why government overhaul mods (Governments+ https://steamcommunity.com/sharedfiles/filedetails/?id=2635869016 ) are mostly recombinations.

**Versioning.** Mods live outside saves; saves store script-keyed state (variables, tradition keys) — remove the mod and the save is orphaned. Checksum gates achievements/ironman. So: **event-and-rule logic is data (interpreted DSL); the simulation loop, AI, and UI are engine.**

## 3. Dwarf Fortress: raws — the maximalist "government as data" case

**Entity raws define a civilization**: `[ETHIC:EAT_SAPIENT_KILL:ACCEPTABLE]` — every ethic pairs a behavior with a reaction on a scale (acceptable → punishable → unthinkable); wars and diplomacy emerge from *comparing* two civs' ethic tables. `[VALUE:CRAFTSMANSHIP:50]` — values run −50..+50 and cross **thresholds that unlock institutions**: 15+ KNOWLEDGE → libraries; 15+ COOPERATION *and* 15+ CRAFTSMANSHIP → craft guilds. Sources: https://dwarffortresswiki.org/index.php/Entity_token , https://dwarffortresswiki.org/index.php/DF2014:Ethic

**POSITION tokens are data-defined government offices** — the closest shipped analogue to CS3.5's mayor/ballot machinery: succession (`SUCCESSION:BY_HEIR|BY_POSITION`), filling method (`ELECTED` — "the population will periodically select the most skill-eligible creature" — vs `APPOINTED_BY:MONARCH`), lifecycle (`REPLACED_BY`, `REQUIRES_POPULATION`, `LAND_HOLDER`), perks/duties (`MANDATE_MAX`, `DEMAND_MAX`, required office/tomb/dining room value thresholds), precedence, gendered names. **Responsibilities** are an enum of engine-implemented duties: functional ones include MILITARY_STRATEGY (commands squads), LAW_MAKING, HEALTH_MANAGEMENT, ACCOUNTING, MANAGE_PRODUCTION, MEET_WORKERS, LAW_ENFORCEMENT vs EXECUTIONS (mutually exclusive); others (COLLECT_TAXES, RELIGION, PATROL_TERRITORY) are **currently unused/flavor** — a data vocabulary that outran the engine. Sources: https://dwarffortresswiki.org/index.php/Position_token , https://dwarffortresswiki.org/index.php/Advanced_entity_position_mechanics , https://dwarffortresswiki.org/index.php/Entity_token

**Raws are COPIED INTO each save/world folder.** Each world carries a frozen private copy of its defining data; editing vanilla raws never touches existing worlds, and you can (carefully) edit a *world's own* raws mid-game. Consequences: perfect isolation between worlds; mid-game raw edits are possible but fragile (duplicate raws → "strange, difficult-to-diagnose problems, and even crashes"; parse-order-dependent tags like `[COPY_TAGS_FROM]`). Source: https://dwarffortresswiki.org/index.php/Raw_file , https://dwarffortresswiki.org/index.php/Modding_guide

**Limits.** Raws are pure declarative tokens — **no expressions, no events, no scripting**; every token's semantics is hardcoded engine behavior (closed source), and things like festival naming stay hardcoded. The community's escape hatch is external: DFHack (Lua over memory). **DF proves an office/ethics vocabulary can be entirely data — and that a token vocabulary without a scripting layer caps out at recombination.**

## 4. Caves of Qud: blueprints + factions, with a compiled escape hatch

**Data layer.** Entity-component architecture surfaced directly as XML: `ObjectBlueprints.xml` defines every object/creature as a blueprint = inheritance parent + a bag of `<part Name="..."/>` elements, where each part name maps to a C# part class and its XML attributes set fields. New objects that recombine ~existing parts need only a small XML snippet. Mods drop their own `ObjectBlueprints.xml`; `Load="Merge"` merges with the base definition, otherwise it replaces wholesale. Factions assigned via the Brain part; ~67 persistent factions + procedural ones, `Factions.xml` data. Sources: https://wiki.cavesofqud.com/wiki/Modding:Objects , https://wiki.cavesofqud.com/wiki/Modding:Overview , https://freehold.atlassian.net/wiki/spaces/CQP/pages/23691295/Object+Modding , https://wiki.cavesofqud.com/wiki/Factions , https://steamcommunity.com/sharedfiles/filedetails/?id=1447088304

**Code layer.** Ship `.cs` files in the mod; the game **compiles them at runtime** into an assembly with full game privileges — so Qud added a **user approval gate**: whenever a C# mod changes, the player must re-approve it before any of its files load (a real, shipped answer to "untrusted code in content"). Harmony is bundled for patching unexposed behavior, documented as **last resort**. Sources: https://wiki.cavesofqud.com/wiki/Modding:C_Sharp_Scripting , https://wiki.cavesofqud.com/wiki/Modding:Harmony , https://freehold.atlassian.net/wiki/spaces/CQP/pages/25690146/.cs+Scripting+Mods , compat/versioning notes: https://wiki.cavesofqud.com/wiki/Modding:Compatibility

**Pain points.** New part *behavior* = C#; some systems simply weren't exposed — devs on record that extending faction **reputation** "is not trivial… something to expose to mods": https://steamcommunity.com/app/333640/discussions/3/359543951729727944/ ; community wishlist of unexposed seams: https://gist.github.com/JHawkley/dfaeeb596fa5835dc37427666481f4f5

## 5. Wildermyth: story/logic content as JSON with an outcome vocabulary

All moddable content is JSON: **Aspects** (named markers on any entity carrying stats/effects; *parameterized aspects work by literal find/replace inside the aspect JSON* — textual macros, same trick as Paradox `$param$`), **Effects** (trigger + **targets** [criteria] + **outcomes**), **Outcomes** (a fixed engine vocabulary of things-that-can-happen: grant resource, apply aspect/theme, start mission, attack roll…), **Events** with comic-panel storytelling, edited via an in-game Content/Comics Editor. **Mod injections** patch specific nodes of base files from a parallel directory tree instead of overwriting whole files (a diff/patch story, like RimWorld's XML PatchOperations). Line: story logic, triggers, abilities, even races are data; a genuinely new *outcome type* means Java. Sources: https://wildermyth.com/wiki/Data_Format_Overview , https://wildermyth.com/wiki/Aspect , https://wildermyth.com/wiki/Modding_Guide , https://wildermyth.com/wiki/Mod_Injection , https://wildermyth.com/wiki/Modding_alternate_races

## 6. Songs of Syx: whole races/cultures in plain text, index-fragile

City-sim at CS3-like scale. Races (with preferences, likings, traits, bios) and rooms are plain text files + sprites — "all you need is a text editor and paint." Known versioning wart: **save compatibility is sensitive to the *count/order* of races and rooms** — mods that only alter existing files are save-safe; adding new ones breaks saves (positional identity, not name-keyed — an anti-pattern worth noting). Java "code mods" exist as a separate, heavier pathway. Sources: https://steamcommunity.com/sharedfiles/filedetails/?id=2446709901 , https://songsofsyx.com/wiki/index.php/Modding , https://steamcommunity.com/app/1162750/discussions/0/594023708174095571/ , https://github.com/4rg0n/songs-of-syx-mod-example , https://mod.io/g/songsofsyx/r/songs-of-syx-modding-handbook

## 7. Battle for Wesnoth: WML + embedded Lua (the cleanest two-tier answer)

Entire campaigns, eras, factions, unit types ship as **WML** (a macro-preprocessed declarative language distributed through an add-on server — content *is* data on the wire). Lua is embedded but scoped: "Lua is only a substitute for **ActionWML**" (the imperative subset) — "you can pretty much write an entire campaign in Lua **apart from unit type definitions and the campaign/scenario definitions**," which stay declarative WML. Lua loads from `[scenario]`/`[era]`/`[resource]` tags. Pattern: **declarative skeleton stays data-data; imperative event bodies get a real language, sandboxed inside the data files.** Sources: https://wiki.wesnoth.org/Luawml , https://wiki.wesnoth.org/ActionWML , https://forums.wesnoth.org/viewtopic.php?t=55149 , https://wiki.wesnoth.org/ScenarioWML

*(Ultima Ratio Regum surveyed but dropped: its culture generation is procedural and in-engine, with no shipped data/mod surface documented.)*

## PAYOFF — patterns for which layers go data-side

1. **Four rungs recur everywhere.** (a) *Vocabulary/values*: enums + weights (DF ethics/values, CK3 tradition parameters, Qud reputation numbers) — always data, cheapest, and powerful when other systems **compare or query** the values rather than switch on identities (DF wars from ethic distance; DF value thresholds unlocking institutions). (b) *Composition*: assemble code-implemented behavior atoms with tuned fields (RimWorld PreceptComps, Qud parts, Wildermyth outcomes) — data expresses *which* behaviors and *how much*, never *new* behavior. (c) *Interpreted logic*: a shipped DSL for triggers/effects/events (Paradox script, WML+Lua) — moves event-shaped and rule-shaped logic to data; deliberately not Turing-complete (no strings, loop caps) for save-safety and perf. (d) *Simulation loop, pathing/AI, UI*: engine code in every single surveyed game. UI is the most stubbornly code-side layer everywhere (RimWorld's mitigation: precept UI is *generated from def fields*, so new data gets UI for free — worth copying).

2. **Government offices are provably data-friendly.** DF POSITION tokens encode succession, election vs appointment, population gates, perks, mandates — a complete constitutional grammar — as flat tokens consumed by hardcoded processes. The catch: the *processes* (holding the election, enforcing the law) are engine verbs; data only wires offices to a fixed verb set, and DF ships dead verbs (COLLECT_TAXES unused). For CS3.5: a cultureway file can own the office/succession/eligibility table on day one even if game.js still owns the election *procedure*.

3. **The save file as the home of culture-logic has one true precedent: DF raws copied per-world.** It buys isolation (worlds never break under mod updates) and mid-world surgery, at the cost of divergence/no-upgrade-path and duplicate-definition crashes. RimWorld's hybrid is the other proven shape: **instance choices in the save (text-editable!), vocabulary in defs, behavior in engine** — with exportable ideoligion preset files as the shareable culture artifact. Paradox is the cautionary tale: saves that merely *reference* external script keys die when the mod disappears.

4. **Every ecosystem grows a code escape hatch, and its governance is a design decision**: C#+Harmony (RimWorld — unofficial, "patch anything"), runtime-compiled C# behind a **player re-approval prompt** (Qud — the shipped model for LLM-authored code in a save file), external DFHack (DF), embedded scoped Lua (Wesnoth — the tidiest). If CS4 is "agents author cultureways," Qud's approval gate + Wesnoth's "declarative skeleton, sandboxed imperative bodies" is the composite to study.

5. **Identity & versioning**: name-keyed defs + explicit merge/patch semantics (Qud `Load="Merge"`, Wildermyth mod injections, RimWorld PatchOperations) age well; positional identity (Songs of Syx race counts) breaks saves; textual macro expansion (Paradox `$$`, Wildermyth find/replace, WML preprocessor) is the recurring poor-man's parameterization — ugly but shipped three times, evidence that cultureway authors will need *some* parameterization primitive.

6. **Hardcoded-pacing smell**: even the most scriptable games nail specific culture-change *rates* into the engine (CK3's 1.66/tick reform, 50-year cooldown) — usually to protect balance/MP-checksum. Flagging which cultureway numbers are sim-conservation-critical (CS3's "resources never conjured") vs freely authorable is the same exercise.
