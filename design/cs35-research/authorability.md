# DESIGN RULES FOR AN AGENT-AUTHORABLE CULTUREWAY LANGUAGE
Research findings for CS3.5 — moving cultureway logic out of game.js into save-file data/code that LLM agents can author safely.

---

## Part A: The evidence base (raw findings by area)

### A1. What makes languages LLM-writable

- **LLMs are dramatically worse at novel/low-resource languages.** The ACM TOSEM survey on LLM codegen for low-resource and domain-specific languages finds Pass@1 gaps persist across model families and scales; data scarcity and unfamiliar syntax are the drivers ([arXiv:2410.03981](https://arxiv.org/abs/2410.03981), [ACM version](https://dl.acm.org/doi/10.1145/3770084)). MultiPL-E (18 languages) confirms performance correlates with language popularity in training data ([MultiPL-E](https://nuprl.github.io/MultiPL-E/), [arXiv:2208.08227](https://arxiv.org/pdf/2208.08227)).
- **The strongest single result: SPEAC.** For a truly novel language (UCLID5), letting the LLM write in a *familiar-feeling intermediate DSL* that is then deterministically compiled to the target raised parse rates from 9–12% (fine-tuning / GPT-4 in-context) to **84.8%** ([arXiv:2406.03636](https://arxiv.org/abs/2406.03636)). Design the surface for the model, compile to the engine format.
- **Grammar prompting**: including the (BNF) grammar in-context materially improves DSL generation ([arXiv:2305.19234](https://arxiv.org/pdf/2305.19234)). Grammar-constrained decoding (SynCode etc.) masks invalid tokens for syntactic validity, but **cannot fix semantic errors** — undeclared symbols, wrong references still occur ([SynCode arXiv:2403.01632](https://arxiv.org/pdf/2403.01632), [Decode-Time Grammars arXiv:2607.18357](https://arxiv.org/abs/2607.18357), which adds environment-aware symbol constraints).
- **Schema-constrained generation is a solved lever for structure.** OpenAI-style structured outputs achieve ~100% JSON-Schema compliance via compiled token-mask grammars vs ~86% for unconstrained function calling ([guide](https://www.digitalapplied.com/blog/openai-structured-outputs-complete-guide), [overview](https://www.protecto.ai/blog/openai-introduces-structured-outputs-for-api-enhancing-reliability-with-json-schemas/)). Claude/Anthropic and open-source stacks (outlines, xgrammar) offer equivalents. Caveat: **"Let Me Speak Freely?"** (EMNLP 2024 Industry) shows strict format constraints measurably degrade *reasoning* quality — the fix is to let the model reason free-form first, then emit constrained output as a separate step ([arXiv:2408.02442](https://arxiv.org/abs/2408.02442), [ACL](https://aclanthology.org/2024.emnlp-industry.91/)).
- **"Familiar syntax, narrow semantics" is a proven production pattern.** Starlark = Python-subset syntax, but deterministic, hermetic, side-effect-free, mostly-immutable data, no unbounded recursion ([spec](https://github.com/bazelbuild/starlark/blob/master/spec.md), [starlark-lang.org](https://starlark-lang.org/)). The stated rationale: familiarity lowers the learning curve while restricted semantics keep evaluation reproducible — exactly the property an LLM's training distribution exploits.
- **GAVEL** (NeurIPS 2024): fine-tuned CodeLlama-13b + MAP-Elites evolution over the **Ludii game description language** generated novel playable board games; the "ludeme" abstraction keeps whole rulesets inside a context window and makes small mutations meaningful ([arXiv:2407.09388](https://arxiv.org/abs/2407.09388), [code](https://github.com/gdrtodd/gavel)).
- **Game Generation via LLMs** (VGDL): GPT-4 with a highly detailed prompt hit 10/10 parsable+logical+mappable maze games; GPT-3.5 got 1/10 fully correct; Gemma-7B 0/10 parsable ([arXiv:2404.08706](https://arxiv.org/pdf/2404.08706)). Model capability and prompt scaffolding dominate; small models can't freestyle a GDL.

### A2. Verification loops for generated content

- **Voyager** (Minecraft): the canonical loop — GPT-4 writes JS skill code against the Mineflayer API; execution errors + environment feedback + self-verification feed back into regeneration; verified skills accumulate in a library ([arXiv:2305.16291](https://arxiv.org/abs/2305.16291), [site](https://voyager.minedojo.org/)). Directly maps to CS3: cultureway scripts run against the sim, failures return as structured feedback.
- **Property-based testing beats example tests for LLM validation.** PGS (Property-Generated Solver): a Generator/Tester agent loop where feedback is the *minimal counterexample violating a property*, not a raw failing test — up to +17.4% absolute pass@1, and it breaks the "cycle of self-deception" where generated tests share the code's flaws ([arXiv:2506.18315](https://arxiv.org/html/2506.18315)).
- **Multi-stage deterministic validation pipelines** are the norm: compile → execute → judge; formal/algorithmic structural checks are more reliable than LLM-as-judge for spec compliance ([LLM4VV arXiv:2408.11729](https://arxiv.org/pdf/2408.11729), [Prompt2DAG arXiv:2509.13487](https://arxiv.org/pdf/2509.13487)).
- **Simulation-based repair**: "Fly, Fail, Fix" iterates game repair with RL + large multimodal models watching actual play ([arXiv:2507.12666](https://arxiv.org/pdf/2507.12666)); LLM agents for automated game testing ([arXiv:2509.22170](https://arxiv.org/html/2509.22170v1)); VGDL paper validates with parsable/logical/mappable rule checks before play ([arXiv:2404.08706](https://arxiv.org/pdf/2404.08706)); PCG survey w/ LLM integration ([UCalgary PDF](https://wpsites.ucalgary.ca/serious-games/wp-content/uploads/sites/136/2024/09/2024aiide-PCG-in-games.pdf)); LLMs-and-games survey/roadmap ([Semantic Scholar](https://www.semanticscholar.org/paper/5a9ce2055a0f200fd53b7eeddf1c05f9e01ccf5a)).
- **CS3-specific asset**: the existing 230-scenario regression suite + seeded headless economy matrix (tools/headless.mjs) is precisely the "oracle" this literature says is the scarce ingredient. A generated cultureway can be auto-validated: does it load, does every scenario still conserve resources, do seeded economy runs stay in sane bands, is the shelter pot solvent under the matrix.

### A3. Safety / capability design

- **Object-capability model** (Mark Miller, E language lineage): authority = holding an unforgeable reference; you deny a script an ability by *never passing it the object*. No ambient authority, no global reach ([E language](https://en.wikipedia.org/wiki/E_(programming_language)), [ocap overview](https://grokipedia.com/page/Object-capability_model), [ocaps guide](https://tersesystems.github.io/ocaps/guide/introduction.html)).
- **Hardened JavaScript / SES / Compartments** — the ocap model *in vanilla JS, same runtime*: `lockdown()` freezes intrinsics, each Compartment gets its own global; a script can only affect what it was explicitly handed; used in production by Agoric smart contracts and MetaMask Snaps to run untrusted third-party JS ([hardenedjs.org](https://hardenedjs.org/), [SES readme](https://github.com/endojs/endo/blob/master/packages/ses/README.md), [Agoric docs](https://docs.agoric.com/guides/js-programming/hardened-js), [practitioner's guide PDF](https://tvcutsem.github.io/assets/HardenedJS_BlueLava2022.pdf)). This is the single most load-bearing finding for CS3 (no build step, vanilla JS): save-resident code can run in a Compartment holding only a cultureway API object.
- **Luau's sandbox recipe** (Roblox, adversarial-scale production): delete `io`/`package`/`load`/`loadstring`, strip `os` and `debug`, freeze all builtin libraries readonly, per-script global tables via `__index` delegation, no `__gc` metamethods, host-driven interrupt/watchdog for runaway scripts ([luau.org/sandbox](https://luau.org/sandbox/), [SECURITY.md](https://github.com/Roblox/luau/blob/master/SECURITY.md)); Script Capabilities beta adds per-container fine-grained capability grants ([overview](https://grokipedia.com/page/Script_Capabilities_Roblox)).
- **Screeps' tick-budget economics**: player scripts get a per-tick CPU limit (1 CPU = 1ms), a 10,000-CPU bucket for bursts, and constant per-action costs (0.2 CPU per game action) — the game stays playable no matter what players write ([docs](https://docs.screeps.com/cpu-limit.html), [architecture](https://docs.screeps.com/architecture.html)).
- **WASM/fuel metering** as the general form: deterministic instruction metering + memory caps + strict import filtering for untrusted plugins (Wasmtime fuel/epochs; Fastly's per-request limits) ([Wasmtime security](https://docs.wasmtime.dev/security.html), [wasm security](https://webassembly.org/docs/security/), [Traction Point moddable via Zig+WASM](https://www.madrigalgames.com/blog/how-i-made-traction-point-moddable-using-zig-and-webassembly/), [DeCl slides](https://www.scs.stanford.edu/~zyedidia/docs/slides/decl-sib24.pdf)).
- **Effect typing** (Koka): every function's type carries its effect row; pure vs effectful is statically distinguished ([Koka book](https://koka-lang.github.io/koka/doc/book.html), [arXiv:1406.2061](https://arxiv.org/pdf/1406.2061)). Academically clean, but the practical industry consensus for embedded scripting is ocap + runtime metering, not effect types.
- **Non-Turing-complete tiers**: CEL — side-effect-free, terminating, linear-time evaluation, "orders of magnitude faster than equivalently sandboxed JavaScript," used for Kubernetes policy ([cel.dev](https://cel.dev/), [cel-go](https://github.com/google/cel-go), [K8s CEL](https://kubernetes.io/docs/reference/using-api/cel/)); Dhall — total language, evaluation always terminates, recursion is a type error, but note termination ≠ fast (pathological exponential terms exist) ([Safety guarantees](https://docs.dhall-lang.org/discussions/Safety-guarantees.html), [rationale](https://www.haskellforall.com/2020/01/why-dhall-advertises-absence-of-turing-completeness.html)).
- **Code-in-save-file precedent**: Factorio ships the scenario's `control.lua` *inside the save*; a save is self-contained and auto-distributed to multiplayer clients; script state persists only through an explicitly serialized `storage`/`global` table, and any state outside it causes desyncs — determinism is maintained by forcing all mutable script state through the save-serialized table and restricting `on_load` ([Tutorial:Scripting](https://wiki.factorio.com/Tutorial:Scripting), [Data lifecycle](https://lua-api.factorio.com/latest/auxiliary/data-lifecycle.html), [Desynchronization](https://wiki.factorio.com/Desynchronization)).

### A4. Declarative-first architectures

- **Data-only defs with inheritance/patching**: RimWorld's XML Defs — "recipes, not the dish"; abstracts + ParentName inheritance + XML patching let a huge mod ecosystem exist mostly without code, with C# only as escape hatch ([XML Defs](https://www.rimworldwiki.com/wiki/Modding_Tutorials/Defs), [inheritance](https://spdskatr.github.io/RWModdingResources/abstracts.html), [Basic Concepts](https://rimworldmodding.wiki.gg/wiki/Basic_Concepts)). Dwarf Fortress raws are the same pattern.
- **ECA rules** (event–condition–action): the classic non-programmer game-logic formalism ([wiki](https://en.wikipedia.org/wiki/Event_condition_action), [Knowledge-Driven Game Design by Non-Programmers arXiv:1404.4713](https://arxiv.org/pdf/1404.4713)); expressiveness ceiling: no planning, no state machines beyond what you encode manually, rule-interaction opacity at scale.
- **Behavior trees vs GOAP vs utility**: BTs = structured/predictable/authorable but combinatorial blow-up at scale; GOAP = emergent planning, harder to author/predict; utility = continuous reprioritization; production practice is **hybrid** (utility selects, BT executes) ([tradeoffs](https://tonogameconsultants.com/game-ai-planning/), [Aversa](https://www.davideaversa.it/blog/choosing-behavior-tree-goap-planning/), [GOBT hybrid paper](https://www.jmis.org/archive/view_article?pid=jmis-10-4-321), [BT intro arXiv:1709.00084](https://arxiv.org/pdf/1709.00084)).
- **LLMs generate declarative structures more reliably than free code**: robust results on LLM→behavior-tree generation via in-context learning and small fine-tunes ([LLM-as-BT-Planner arXiv:2409.10444](https://arxiv.org/abs/2409.10444), [training LLMs for BT generation arXiv:2401.08089](https://arxiv.org/pdf/2401.08089)); GAVEL's ludemes are likewise a declarative tree. Declarative nodes are individually validatable and constrained-decodable (each node = schema).
- **The hybrid ceiling-breaker**: declarative skeleton + small expression hooks (CEL-class) covers most of the gap before you need real scripts — this is Kubernetes' exact architecture (YAML + CEL) and RimWorld's (XML + C# hooks).

## Part B: The design rules (numbered commitments, each with its evidence)

**1. The cultureway format is a layered tower: JSON data → expressions → scripts, and every feature lives at the lowest layer that can express it.**
Layer 0: pure data defs (RimWorld/DF-raws pattern — offices, rituals, calendars, ballot types, purse rules as JSON). Layer 1: side-effect-free, terminating expressions (CEL-class) for formulas — eligibility, tax rates, vote weights. Layer 2: sandboxed procedural hooks only where data can't reach (novel counting ceremonies, multi-step rituals). Evidence: RimWorld's ecosystem thrives mostly at layer 0; Kubernetes ships layer 0+1 at planetary scale; CEL's terminating linear-time evaluation is engine-safe by construction; the LRPL survey says every layer of "just data" you add is a layer the LLM can't get wrong. ([RimWorld Defs](https://www.rimworldwiki.com/wiki/Modding_Tutorials/Defs), [cel.dev](https://cel.dev/), [arXiv:2410.03981](https://arxiv.org/abs/2410.03981))

**2. Do not invent a novel syntax. Layer 0/1 is JSON validated by JSON Schema; layer 2 is a JavaScript subset.**
LLMs collapse on unfamiliar surface syntax (9–12% parse rates on a novel language vs 84.8% via a familiar intermediate — SPEAC); JSON-Schema-constrained generation is ~100% structurally valid off the shelf; JS is CS3's native tongue and among the highest-resource languages in every training corpus (MultiPL-E). Semantics can be as narrow as you like — Starlark proves familiarity of syntax and restriction of semantics are independent axes. ([arXiv:2406.03636](https://arxiv.org/abs/2406.03636), [structured outputs](https://www.protecto.ai/blog/openai-introduces-structured-outputs-for-api-enhancing-reliability-with-json-schemas/), [MultiPL-E](https://nuprl.github.io/MultiPL-E/), [Starlark spec](https://github.com/bazelbuild/starlark/blob/master/spec.md))

**3. Ship the cultureway schema (and API surface) as a machine-readable artifact that goes into the authoring agent's prompt.**
Grammar prompting improves DSL generation; the VGDL result showed detailed spec-in-prompt was the difference between 1/10 and 10/10 correct; GAVEL worked because whole rulesets fit in context. CS3.5 should treat "the JSON Schema + the capability API's typedefs + 2–3 exemplar cultureways (the Crabocracy itself, re-expressed in the format)" as a published prompt-kit — the Crabocracy-as-data is simultaneously the reference implementation, the regression baseline, and the few-shot exemplar. ([arXiv:2305.19234](https://arxiv.org/pdf/2305.19234), [arXiv:2404.08706](https://arxiv.org/pdf/2404.08706), [arXiv:2407.09388](https://arxiv.org/abs/2407.09388))

**4. Constrain the emission, not the thinking.**
Format-restricted generation degrades reasoning (Let Me Speak Freely), so the CS4 authoring loop should be: agent designs free-form → emits schema-constrained JSON per component. Component-at-a-time emission (one office, one ritual, one rule) keeps each generation small, schema-checkable, and individually repairable — the modular-pipeline result. ([arXiv:2408.02442](https://arxiv.org/abs/2408.02442), [Prompt2DAG](https://arxiv.org/pdf/2509.13487))

**5. Invariants live in the engine, never in the cultureway. Conservation and remit are physically unexpressible violations, not linted ones.**
The engine's mutation API is the only way a script touches the world, and that API simply has no "create resource" verb — transfers only, conservation proved per movement exactly as CS3 does today; the government object's API reaches the shelter and the pot and nothing else ("local government, not gods" as an API surface, not a rule). Evidence: this is the ocap doctrine (deny authority by not passing the reference — E/Miller), Luau's "remove the unsafe library entirely" approach, and multiplayer-games' server-authoritative doctrine. A hostile script that says "conjure 50 kelp" must be a *type error against the API*, not a caught cheat. ([ocap](https://grokipedia.com/page/Object-capability_model), [luau.org/sandbox](https://luau.org/sandbox/))

**6. Layer-2 scripts run in SES/Hardened-JS Compartments holding exactly one object: their capability bundle.**
`lockdown()` + one Compartment per cultureway, global object containing only the granted API (read-views of relevant state + the remit-scoped mutators + a seeded RNG handle). No `Date`, no `Math.random`, no engine internals. This is production-proven for hostile third-party JS in the same runtime (Agoric, MetaMask Snaps), needs no build step, and is a single vendored `ses` file — compatible with CS3's no-build constraint. ([hardenedjs.org](https://hardenedjs.org/), [SES](https://github.com/endojs/endo/tree/master/packages/ses), [Agoric](https://docs.agoric.com/guides/js-programming/hardened-js))

**7. Determinism is enforced the Factorio way: all script state lives in one engine-serialized table, all randomness comes from the handed-in seeded RNG, and anything else desyncs the replay.**
Factorio proved code-in-save works at scale and documented the exact failure mode: script state outside the serialized `storage` table breaks deterministic replay. CS3's seeded sim needs the same contract — cultureway state is a JSON subtree of the save the engine owns and serializes; scripts are stateless functions over (their state subtree, the capability bundle). This also makes cultureway state saveable/exportable for free in CS3's plain-JSON slots. ([Data lifecycle](https://lua-api.factorio.com/latest/auxiliary/data-lifecycle.html), [Desynchronization](https://wiki.factorio.com/Desynchronization), [Starlark determinism](https://starlark-lang.org/))

**8. Meter the tick: per-hook instruction/op budget with a Screeps-style constant cost per API call, and a defined degrade path.**
A cultureway must not stall the tick. Layer 1 can't (terminating by construction); layer 2 gets a fuel budget (count ops in the interpreter, or a Luau-style watchdog) plus fixed per-API-call costs; on exhaustion the hook is aborted, its state rolled back, and the engine's default behavior runs — the sim never stops. Evidence: Screeps (CPU/tick + bucket + 0.2/action), Wasmtime fuel, Luau interrupts. ([Screeps CPU](https://docs.screeps.com/cpu-limit.html), [Wasmtime security](https://docs.wasmtime.dev/security.html), [luau.org/sandbox](https://luau.org/sandbox/))

**9. The 230-scenario suite + headless economy matrix is the cultureway acceptance oracle: no generated cultureway is "valid" until it survives seeded simulation.**
Validation pipeline (all deterministic before any LLM judgment): (a) JSON Schema check per component; (b) static reference check — every id resolved, every hook's API usage within grant (the semantic layer grammar-constrained decoding can't cover); (c) property checks over seeded headless runs — conservation ledgers balance, pot solvency, elections terminate, no starvation cliffs vs baseline matrix bands; (d) full scenario suite where applicable. Failures return as *minimal counterexamples* (seed + tick + violated property), which is the feedback form shown to best drive LLM repair. This is Voyager's loop with CS3's suite as the environment. ([PGS arXiv:2506.18315](https://arxiv.org/html/2506.18315), [Voyager arXiv:2305.16291](https://arxiv.org/abs/2305.16291), [LLM4VV](https://arxiv.org/pdf/2408.11729))

**10. Prefer declarative process shapes with named extension points over free orchestration code.**
Political processes (nominate → campaign → poll → count → seat) should be declared as data — phase machines / ECA rules / BT-like trees — with expression hooks at named points (eligibility(), weight(), quorum(), tiebreak()). Evidence: LLMs generate BT/tree structures more reliably than equivalent free code; each node is schema-validatable; hybrids (declarative skeleton + scored/expression leaves) are the production norm in game AI; ECA's known ceiling (no planning, rule-interaction opacity) is acceptable because cultureways are *institutions*, which are naturally phase-and-rule shaped. ([LLM-as-BT-Planner](https://arxiv.org/abs/2409.10444), [game AI tradeoffs](https://tonogameconsultants.com/game-ai-planning/), [ECA for non-programmers](https://arxiv.org/pdf/1404.4713))

**11. Design the vocabulary as "ludemes": small, named, composable units sized so one component fits one generation and one mutation is meaningful.**
GAVEL's success hinged on Ludii's ludeme granularity — whole games fit in context, and evolution/repair operates per-ludeme. Cultureway components (a ritual, an office, a levy, a franchise rule) should be similarly self-contained and referenced by id, enabling GAVEL-style evolutionary search and per-component repair rather than whole-file regeneration. ([arXiv:2407.09388](https://arxiv.org/abs/2407.09388))

**12. Interface opacity stays a bug: every engine rejection — schema, capability, budget, conservation — must be a legible, structured error, because the LLM repair loop is only as good as the error channel.**
Voyager and the generate–validate–repair literature agree the feedback signal is the bottleneck; PGS shows minimal, property-oriented feedback is what repairs code. The same errors that CS4 agents consume are the ones human authors will read — one investment, both audiences. ([Voyager](https://voyager.minedojo.org/), [PGS](https://www.alphaxiv.org/overview/2506.18315v1))

**13. Reserve heavyweight isolation (WASM, separate VM, effect-typed language) as a non-goal for CS3.5.**
The threat model is "confused/hostile generated JS inside a cooperative single-player sim," not native-code escape. SES compartments + engine-owned invariants + fuel metering cover it with zero build-step cost; WASM/Koka-class machinery buys marginal safety at total-architecture cost. Keep the tower's layers narrow instead — CEL-class layer 1 already gives most scripts nothing to escape *with*. ([hardenedjs.org](https://hardenedjs.org/), [cel-go](https://github.com/google/cel-go), [Koka](https://koka-lang.github.io/koka/doc/book.html))

## Key tensions for the synthesizer

- **Rule 2 vs expressiveness**: JSON-as-language caps how "programmable" cultureways feel; the bet (backed by RimWorld/K8s) is that layers 0+1 cover ~90% of cultureway variation and layer 2 stays rare. If layer 2 turns out to dominate, revisit with a Starlark-style JS-subset interpreter rather than loosening the sandbox.
- **Rule 4 vs Rule 3**: schema-in-prompt plus free-form reasoning then constrained emission is a two-pass authoring cost; acceptable for CS4's "build me a cultureway" cadence (seconds don't matter).
- **Terminating layer 1 ≠ cheap layer 1** (Dhall caveat): still meter expression evaluation count per tick.
- **Grammar/schema constraints guarantee syntax, never semantics** (SynCode/DTG finding): the reference-resolution pass (rule 9b) is not optional.
